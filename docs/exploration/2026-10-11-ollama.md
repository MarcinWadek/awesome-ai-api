## Stream contract and limitations

- Mock upstream is NDJSON; public backend is SSE. Each JSON payload is pretty
  printed across multiple `data:` lines; join them with newlines until a blank
  line, then JSON.parse. Preserve whitespace inside response/content strings.
- Ordinary mock streams append one terminal done event. Tool flow forwards each
  upstream done event and continues with backend role=tool messages (done=false)
  and further upstream calls. Consume the complete HTTP body, not the first done.
- Tool call IDs and timestamps change. Selected scenario text, calls and
  arguments are canned. Product tool payloads use current catalogue data.
- Observed list payload: page=0, size=25, total=2, products containing id/name.
  Snapshot matched product 1, including price=999.99 and stockQuantity=47.
- Final mock prose instead says $999 and 5 units. See the
  [mock grounding bug report](../ollama-mock-bug-report.md). Do not assert that
  canned prose establishes correct prices or inventory.
- Probes used Playwright's buffered response body; they establish SSE framing
  and complete event sequences, not first-token latency or proxy flush timing.
- Direct mock endpoints, real-model behavior, model-not-found propagation,
  upstream failure during streaming, rate limits, iteration caps, and system
  prompt effectiveness were not live-tested. No 404 test is justified here.
