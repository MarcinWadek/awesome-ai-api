# QR creation exploration

Observed on 20 October 2026 at `https://awesome.byst.re` (`api` project).

Sources: live `/v3/api-docs` (retrieved today), saved `docs/api-docs.json`, and
read-only backend `QrController`, `CreateQrDto`, `QrService`. No course solutions
were used. The contract requires Bearer authentication, JSON `{ "text": string }`
with nonblank text, and documents 200 PNG, 400 JSON validation, 401 JSON errors.
The service generates a 400 by 400 image.

Two independent live runs used disposable registered client users. Each signed
in successfully (200); each was forgotten in `finally` (204). Credentials and
tokens were neither printed nor saved. Payloads were
`{"text":"https://example.invalid/qr-core"}` and `{"text":"   "}`.

| Authentication / Accept | Valid text | Blank text |
| --- | --- | --- |
| Valid Bearer / `application/json` | 401 JSON `{"message":"Unauthorized"}` | Same 401 |
| Valid Bearer / `image/png` | 200 `image/png` | 400 JSON `{"text":"Text is required"}` |
| Valid Bearer / `image/png, application/json` | 200 `image/png` | Same 400 JSON |
| None / `image/png, application/json` | 401 JSON `{"message":"Unauthorized"}` | Not probed |

The successful PNGs were 458 bytes, with signature `89504e470d0a1a0a` and IHDR
dimensions 400 by 400. JSON-only Accept is incompatible with the documented
success representation, but its authentication error is misleading: the same
token succeeds when only Accept changes. See the [negotiation defect](../qr-accept-bug-report.md).

Use the dual Accept header in the new QR client to override the project's JSON
default and explicitly accept documented errors. Keep the three requested core
cases; do not encode the misleading 401 as expected negotiation behavior.
Deferred: QR payload decoding, large text/encoding limits, rate limits and an
automated incompatible-Accept regression. No persistent QR resource needs cleanup.

Raw sanitized observations and the ad hoc runner are gitignored under
`exploration-results/2026-10-20-qr-traffic.json` and `qr-traffic-probe.cjs`.
